# 夹爪命令频率、消息格式与重启后复测（2026-11-04）

## 命令频率

目前没有固定50Hz/100Hz的实机夹爪控制调度器。之前“100次测试”指样本次数，测试是写一次→等确认→读回→下一次，受USB/WSL和串口耗时影响，不是声明100Hz。2Mbps是串口的比特传输速率，不能当作动作更新频率。约2ms的确认中位数也不代表已验证500Hz机械控制。

50Hz表示每20ms有一次目标更新机会，100Hz表示每10ms一次，是后续调度器的配置与验收对象。当前诊断是启动时写若干配置，然后分段发送单个目标，期间密集读反馈；没有持续以某个固定频率发送开/关指令。

在电机开启且控制行为正常时，一个位置目标发送后，夹爪内部控制器会持续追踪这个目标，直到收到新的目标或关闭使能；不需要电脑每隔几毫秒重发同一数值才会动作。内部控制器运行频率本轮没有验证，不凭空写成1kHz。

## 两层消息格式

程序的物理夹爪动作是一维连续数：绝对闭合比例0..1，0为设备位置最小端，1为最大端。它不是“是否滑移”的二值量，也不是运动增量。示例0.5按当前0..1150位置范围映射到整数575；这是位置计数范围的一半，不是已经标定的毫米开口一半。normalized=True的网络训练归一化输出不能直接发送。

线上实际发送的是DYNAMIXEL2.0二进制包，由官方SDK编码，不是JSON字符串或一个裸浮点数：

```text
包头 + 设备ID + 包长度 + 写入指令 + 寄存器地址 + 数据 + CRC校验
```

给当前RN夹爪ID1的目标位置寄存器596写入575，四字节小端编码。以下包仅离线生成解释，**没有发给实机**：

```text
FF FF FD 00 | 01 | 09 00 | 03 | 54 02 | 3F 02 00 00 | 12 85
包头         ID   长度    写入   地址596   目标575        CRC
```

位置是4字节整数；目标速度、电流、加速度是另外的寄存器写入。收到状态包确认只说明设备接收了指令；实际开合位置需再读实测位置寄存器611。串口每字节还包含起止位，上述16字节在2Mbps下的理想线上时间约80微秒，但真实往返含USB、WSL、设备处理和等待，不能用80微秒代替约2ms实测确认耗时。

## 用户重启后的两次复测

用户重新放置夹爪并重启控制板后，USB仍连入WSL，模式5、位置502/503、目标502，电机关闭，供电24.2V、43℃、硬件错误0。

1. `outputs/gripper-bench-20261104-reboot-hold/`：设置约100.5mA、速度0.456rpm、目标502，短暂使能。原先约1A启动尖峰未重现；采样电流最大绝对值26计数，约104.5mA。但目标保持502时，实测502→497，越过诊断下界498，触发关闭。关闭使能后仍有被动/残余位置变化，不能把软件发出关闭等同于机械立即锁死。
2. `outputs/gripper-bench-20261104-reboot-refresh-hold/`：按官方示例启发验证另一种顺序：零电流预置，使能后将目标从482刷新为481，再计划逐级增加电流。刚进入零电流阶段就读到-103计数，按表约-414mA，立即关闭；没有执行后续电流爬升和开合。此结果不能证明初始化顺序已修复。

两次均确认电机关闭后才恢复原RAM配置；未修改EEPROM、模式、PID或固件。正常运动锁保留。当前证据不足以确认是反馈偏差、初始化/控制器问题、机械回弹还是其他硬件因素；下一步应先用官方DYNAMIXEL Wizard交叉核对，而不是提高电流或扩大目标。

最终只读复核后：位置470、目标预置470、使能0、电流0、速度反馈0、供电24.2V、44℃、硬件错误0。证据`outputs/gripper-bench-20261104-reboot-summary.json`。

结论：重启后仍没有通过受控保持/开合；通信格式与目标收发可用，不代表动作跟踪已正常。基准入口修改仅用于隔离诊断，生产arm()仍拒绝运行。34项软件测试通过不替代上述机械测试结果。
